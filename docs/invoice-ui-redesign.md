# 請求書UI 再設計（freee請求書アプリの分析 → 本システムへの適用）

オーナー提供のスクリーンショット（freee請求書 iOSアプリ「請求書詳細」）を正本として分析した。
Web上の公開仕様は本作業環境から取得できなかった（ネットワーク遮断）ため、**画面の実物のみ**を根拠にしている。

---

## 1. freee請求書アプリが採っている構造

### 1.1 画面の骨格

| 位置 | 要素 |
|---|---|
| 最上部 | 戻る「請求書」／ タイトル「請求書詳細」／ ⋯（その他操作） |
| 本文 | **iOS標準のグループ化フォーム**（角丸カードの縦積み）を上から下へスクロール |
| 最下部固定 | 主要CTA「**送付**」＋ 共有アイコン |
| タブバー | 見積書 / 納品書 / 請求書 / 領収書 / 取引先 |

**紙のプレビューを編集画面にしていない。** 編集は完全にフォーム、紙の姿はPDFで別に見る、という分離。

### 1.2 本文の並び（上から）

1. **取引ステータス**（例: 登録待ち）— 最初に状態を見せる
2. **取引先 / 敬称**（各行に ⓘ で詳細へ）
3. **自社情報**（ⓘ）
4. **件名 / 請求書番号 / 枝番 / 請求日 / 入金方法 / 入金期日**
5. **現場名の見出し行**（「読売ランド水族館」「品川新築学校」…）でグルーピング
6. **明細カード** — 下記1.3
7. **集計**: 小計(税別) / 消費税 / 10%対象＋消費税 / 0%対象＋消費税 / **合計**（太字）
8. **備考** / **社内メモ**（自由入力の枠）
9. **書類を取り消す**（赤字）＋ 効果の説明文 ＋ ヘルプリンク

### 1.3 明細の見せ方 ← 最重要

freee は明細を**表にしていない**。1明細＝1カードで、

```
電気工事業　A
                                    350,000 円
                                    税率10%
                                    25,000 円×14 (式)
```

- 品名は左・大きめ
- **金額は右に大きく**
- その下に小さく **税率** と **単価 × 数量 (単位)**

この「**単価 × 数量** を必ず併記する」設計が効いている。
今回の「残業1.5hが2hと表示され、`2 × ¥3,906 = ¥5,859` になっていた」不具合は、
この形式なら発行前に人間の目で必ず気づける。

## 2. 本システムの現状との差分

| 論点 | freee | 本システム（改修前） | 判定 |
|---|---|---|---|
| 明細の表現 | カード（金額大・内訳小） | 6列テーブル | ✗ スマホで列が潰れ「電気工事業C」が縦書きになる |
| 単価×数量の併記 | あり | なし（数量列と単価列が離れている） | ✗ 検算できない |
| 編集画面 | フォーム | 紙プレビュー風の表 | ✗ |
| プレビュー | PDF別画面 | PDFと別レイアウトの独自HTML | ✗ 出力と食い違う |
| 現場グルーピング | 見出し行 | text行で実装済み | ○ 同等 |
| 税率別内訳 | 常時表示 | PDFのみ | △ |
| 破壊的操作 | 最下部・赤字・説明文 | 分散 | △ |
| 主要CTA | 下部固定 | 通常ボタン | △ |

## 3. 今回の改修で入れたもの

- **プレビューを PDF の 1:1 レプリカに置き換え**
  `client/src/components/InvoicePreview.tsx` を、`server/pdfInvoice.ts` と同じ
  A4絶対座標（595.28×841.89pt）で描き、表示時にコンテナ幅へ `transform: scale` する方式に変更。
  順序・枠・列・透かし・社印座標をPDFと共有するので、**プレビューと出力が構造的にズレない**。
  スマホ用に「原寸で見る / 画面幅に合わせる」トグルを付けた。
- **数量の保存規約を統一**（`shared/invoiceQuantity.ts`）。詳細は §5。
- 入金期日をプレビュー画面から直接設定できるようにし、**振込先が未登録なら理由を明示**。
- ロゴの調整可動域を拡大（大きさ ×0.3〜×8、位置 X −460〜+100pt / Y −140〜+620pt）。

## 4. 未着手（オーナー判断待ち）

**明細編集タブの freee 式カード化**。現状の6列テーブルをやめ、

```
┌────────────────────────────────┐
│ 電気工事業A                     │
│                     ¥350,000   │
│ 税率10%                         │
│ ¥25,000 × 14 日                 │
│ [編集] [削除]                   │
└────────────────────────────────┘
```

- 現場見出し（text行）はセクションヘッダとして描く
- 編集はカードをタップ → ボトムシートで 数量/単位/単価/税率
- 集計カードに「10%対象 / 0%対象」の内訳を常時表示
- 「請求書を取り消す」は最下部・赤字・説明文つきに移動
- 主要操作（PDF出力・送付）は下部固定

対象は `client/src/pages/AppInvoices.tsx`（取引先請求書）と
`client/src/pages/AppMyClosing.tsx`（作業員請求書）。両方とも同じカード部品を使う。

## 5. 数量の保存規約（2026-08 変更）

**DBの `quantity` は単位に関係なく必ず ×10 の int**（15 = 1.5、220 = 22.0）。
変換は **`server/db.ts` の invoice item アクセサだけ**が行い、
ルーター・PDF・画面はすべて人間単位（1.5）を扱う。実装は `shared/invoiceQuantity.ts`。

変更前は「単位が『日』のときだけ ×10、それ以外は素の値」という規約が
サーバー・PDF・画面の10か所以上に散らばっており、次の不具合が同時に起きていた:

- `invoice_items` 単位「時間」: 残業 1.5h が int 丸めで **2** と表示（金額は 1.5h で正しい）
- `worker_invoice_items` 単位「日」: 半日を含む月 21.5日 → **22日**
- `AppReceivables` / connect の受領請求タブ: 単位を見ずに常に `/10` していたため「時間」明細が 1/10 表示

マイグレーションは `drizzle/0047_invoice_quantity_times10.sql`。
既存データの `worker_invoice_items` は ×10 化前に既に int 丸めされているため、
半日を含む過去月の日数は**再生成しないと直らない**（金額は元から正しい）。
