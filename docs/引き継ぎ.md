## 1. プロジェクトとは何か・完成の定義

- **何**: 電気設備工事業「充寵グループ」の業務管理システム。コーポレートサイト＋業務アプリ `/app`。
- **技術**: Express + tRPC v11（単一 appRouter: `server/routers.ts`）／ MariaDB + drizzle-orm ／ React + Vite + wouter ／ vitest。
- **公開**: `https://www.juchou-group.com`（自社 VPS 24 時間稼働）。**Manus は撤去済み**。
- **完成の定義**: 単一の「リリース版」は無い。**運用中に業務要件が増えると機能追加していく継続的プロダクト**。現時点の残作業は §7 の「次にやるべきこと」。

## 3. 試したがダメだったこと（再発防止・時間浪費防止）

| 試みたこと | 結果 | 理由 | 恒久対処 |
|---|---|---|---|
| 手書き `0018_worker_invoices_v1.sql` 等を MariaDB 11 で実行 | `ER_PARSE_ERROR(1064)` / `1050`(既存) / `1061`(既存 index) | drizzle-kit 生成版と重複。DDL 方言差 | 該当ファイルを **`SELECT 1;` (no-op) 化**して残す。journal を消すと migrator 整合が崩れるので **journal は保持**（`docs/DEPLOYMENT.md` §DB マイグレーション） |
| Cookie を `sameSite: "strict"` にする | ログイン不能 | 別ドメインからのリダイレクト遷移で cookie が付かない | **`sameSite: "lax"` を固定**（`server/_core/cookies.ts`）。ここを変えるとログイン不能。 |
| `server/_core/vite.ts` で `vite` を **通常 import** | 本番コンテナが起動時にクラッシュ | 本番 image に vite は入っていない（devDeps） | **動的 import (`await import("vite")`)** に固定。壊すと起動しない。 |
| `verifySession` で `appId` を必須にする | ログイン不能 | 一部フローで appId が空で来る | **openId のみ必須／appId 空を許容**（`server/_core/sdk.ts`）。 |
| Caddy 設定を SFTP 上書きしたが caddy コンテナ非再作成 | 新ドメイン（`storage.juchou-group.com`）の証明書が取れない | 他サービス追加だけでは caddy が再作成されない | **`docker compose up -d --force-recreate caddy`** を明示（`docs/DEPLOYMENT.md`） |
| Watchtower 環境変数なしで起動 | `client version 1.25 too old` で自動更新失敗 | 新しめ Docker daemon 対策 | **`DOCKER_API_VERSION: "1.44"` を設定**（同上） |
| `Caddyfile` が無い状態で `docker compose up` | Docker が同名ディレクトリを誤作成し `not a directory` | Bind mount の自動 mkdir | ファイルを先に置く／存在確認してから up |
| MariaDB の JSON 列を **配列としてそのまま使う** | 型不整合・空扱いになる | MariaDB は json 列を**文字列で返す** | **`normalizeZone` / `normalizeMaterialPreset` 方式**（`server/genba/db.ts`）で `JSON.parse` フォールバック |
| 途中経過を細かく報告 | オーナーから明示的に不要と指定 | 完了・要判断・失敗のみ欲しい | CLAUDE.md「Claude 作業ポリシー」 |

## 4. 環境の落とし穴

### 4.1 バージョン制約
- **Node**: CI は `node-version: 22`（`.github/workflows/ci.yml`）。ローカルも 22 系推奨。
- **pnpm**: `packageManager: pnpm@10.4.1`（package.json）／ `engines.pnpm: ^10.15.1`。**`corepack` 有効化 or `pnpm@10` インストール**必須。npm/yarn は不可（lockfile が `pnpm-lock.yaml`）。
- **MariaDB**: 11 系（本番＋CI の `migration-test`）。MySQL でも一応動くが SQL 方言差（JSON 列返却型・予約語）に注意。
- **Docker**: 本番は Docker daemon が新しめのため Watchtower は `DOCKER_API_VERSION=1.44` 必須。

### 4.2 テスト実行時の既知の問題（移行元で確認済み）
- `pnpm test` は **89/90 suites pass**（845 test pass / 3 skip / 0 test fail）。
- 唯一失敗: `server/pdfMerge.test.ts` が `pdf-lib` を解決できず suite ロードで失敗。
  - `pdf-lib ^1.17.1` は package.json に登録されているが、**このクラウド環境の `node_modules/` に実体が無い**（`node_modules/.pnpm/` にも無し）。
  - **原因未特定**。移行元セッションの `pnpm i` が不完全だった可能性が高い。
  - **移行先で最初にやること**: `pnpm i --frozen-lockfile` を実行し、`node_modules/pdf-lib` が存在するか確認 → 存在すれば `pnpm test` は 90/90 になる想定（未検証）。存在しない場合は `pnpm add pdf-lib@^1.17.1` で明示追加を試す前に、依存グラフ（`pnpm why pdf-lib`）を確認すること。
- CI(`ci.yml`) は毎コミット走っている（オーナー合意の自動マージがそこを通っているため、本質的には通っているはず）。

### 4.3 認証の壊しやすさ（**触るときは慎重に**）
- `server/_core/cookies.ts` の `sameSite: "lax"`
- `server/_core/sdk.ts` の `verifySession`: openId のみ必須／appId 空許容
- `server/_core/vite.ts`: vite は**動的 import**
- いずれか壊すと**ログイン不能 or 本番起動クラッシュ**（`CLAUDE.md`・`docs/DEPLOYMENT.md` に既記）

### 4.4 MinIO / ストレージ
- 本番 URL: `https://storage.juchou-group.com`（Caddy → `minio:9000`）
- ブラウザから直取得する presigned URL 方式のため `S3_ENDPOINT` は**公開ドメイン**である必要がある（`localhost` 等ではだめ）
- **旧 Manus 時代の AWS 上のファイル（`d2xsxph8kpxj0f.cloudfront.net`）は MinIO 未移行**。DB には旧 URL が入っているが Manus 停止済みのため表示できない可能性がある（要確認）。

### 4.5 マイグレーション
- 実行される SQL は `drizzle/meta/_journal.json` に載っているものだけ。それ以外の `.sql` は「死にファイル」（詳細 `docs/DEPLOYMENT.md`）
- 新規マイグレーションは `pnpm db:push`（`drizzle-kit generate && drizzle-kit migrate`）でローカル生成。既存テーブルへの `ALTER` が出たら**停止・報告**（genba ルール）
