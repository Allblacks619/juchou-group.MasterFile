## 2. 決定事項とその理由（コードから読めないもの）

### 請求・支払の日数計算（重要・一度直した）
- **日数は「出面日数（実働の重複なし日数）」で数える。稼働時間からは換算しない。** 旧実装は `Σ(hoursWorked)/8` で日数を出していたため、同日重複記録や8時間以外の入力で出面表と食い違った（大木早苗: 出面14日 vs 支払15日 の指摘が発端）。
  - 理由: `hoursWorked`（時間）は将来、作業員が社員化した際の**労基法上の時間記録**として残す方針。billing の日数根拠には使わない、とオーナーが明示。
  - **半日(half_day)は 0.5 日**。ただし「40h ÷ 8 = 0.5」という時間換算ではなく、**workType のカテゴリとして 0.5**（`workedDayValueTimes10`）。時間から換算しない方針の一貫性のため。
  - 実装: `shared/attendanceStatus.ts` の `workedDayValueTimes10`、`server/routers.ts`(ensurePaymentRowsForProjectMonth) / `clientInvoiceV2Builder.ts` / `workerInvoiceV2Core.ts` の3か所。
- **残業の band 分け**（時間外×1.25 / 深夜×1.50、昼勤は5h超で深夜、夜勤は全て深夜）は CLAUDE.md §請求ルール参照。ここは触っていない（触ると壊れる delicate ゾーン）。

### 権限モデル（このセッションの主成果・大きく再設計）
- ロールは `super_admin / admin / manager / worker / guest` の5段階（DB enum に旧 `leader` も残るが**サーバー実効では worker 扱い**。新規に使わない）。
- **ロール（土台）＋ 個人別「エリア別 表示/ブロック設定」** の2層構成にした（`shared/permissionAreas.ts`）。8エリア: `billing(取引先請求) / payments(作業員支払) / rates(単価管理) / employees / projects / attendance / closing / company`。
  - `super_admin/admin` は常に全エリア可（設定する側なので override 対象外）。
  - `manager` はエリアごとの既定（`managerDefault`）。**`billing` のみ manager 既定ブロック**（下記オーナー指示）。他は既定可、`deny` で個別に隠せる。
  - `worker/guest` は既定で全不可、`allow` で個別付与（＝実質の中間ロール。「出面だけ任せる作業員」等）。
  - 保存: `users.permissionOverrides`（JSON, migration 0042）。判定は `resolveAreaPermission`。
  - サーバー: `areaProcedure(area)` 系（`billingProcedure` 等）で `leaderOrAdminProcedure` を全面置換（audit ルーターのみ旧ガードのまま=意図的）。手動 `isManagerLike` 判定もエリア判定へ移した。
  - クライアント: `RoleGuard` の `area` prop / `AppLayout` の `NAV_AREA_BY_LABEL`（ナビ連動）/ `AppEmployees` の「表示設定」ダイアログ。
- **取引先請求単価(clientRate)・請求額は管理者(admin)以上のみ**（オーナー指示 2026-07）。理由: 責任者(manager)に売上単価を見せたくない。`rate` API は billing 権限が無いと `clientRate` をサーバー側で `null` にマスクして返す（画面の入力欄も出さない）。作業員には元々見えていない（自分の支払単価のみ）ことを監査で確認済み。
- 詳細な「誰に何が見えるか」マトリクスと修正済みセキュリティ穴の一覧は **`docs/permissions-audit.md`** が正本。

### 画面設計・命名
- **月締め系3画面は「メニュー的に別々」で維持**（オーナー指示: 支払管理／入金管理／作業日報を1画面に**統一しない**。見せ方だけ改善する）。過去に「統一」と表現して却下された（§6 参照）。
- 「月締めV2」→「月締め管理」等の**紛らわしい名称整理は文言のみ**で実施（PR #179, まだ未マージ。§4）。ラベルキー名は変えない（コード参照が壊れるため表示文字列だけ変更）。

### ダッシュボードのクリア
- 出面セルの「クリア」は**レコード削除**であるべき（旧実装は `workType="absence"` で欠勤マーカー上書きしていて、day_off と同じ「休」表示になり「消えたように見えない」不具合だった → 削除に修正済み, PR #147）。

## 3. 試したがダメだった / 確認して不可能だったこと

- **`drizzle-kit generate` の非対話実行は不可**（このコンテナ環境）。カラム rename/追加時に対話プロンプト（columnsResolver）で無限待ちになり、pseudo-TTY でも詰まる。
  - 対処: **migration SQL を手書きし、`drizzle/meta/_journal.json` に手でエントリ追加**する（0042 はこの方法で作成）。`ALTER TABLE ... ADD ...` 程度なら手書きで十分。CI の `migration-test`（MariaDB 11 で全 migration を流す）が非互換を検出するので、それを通れば安全。
- **journal 外の `.sql` は実行されない**（死にファイル）。過去の手書き migration で MariaDB 11 パースエラーになったものは `SELECT 1;` に no-op 化して journal エントリは保持済み（消すと migrator の整合が崩れる）。詳細 `docs/DEPLOYMENT.md`。
- **サブエージェント（worktree isolation）の未コミット作業は、セッション上限で強制終了されると worktree ごと消えて復元不能**。本セッションで UI デザインパス(Opus)と権限残渣監査(Sonnet)がこれで消えた（§5）。→ **エージェントには「コミットまで」を完了条件に含めること**（本セッションの文言整理エージェントはコミット済みだったので回収できた）。
